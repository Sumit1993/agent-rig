Summon grammar: the three verbs

Bare PR comments, org members only (OWNER, MEMBER or COLLABORATOR). The comment body is read only by workflow contains() expressions. It never reaches a prompt or a shell string.

CommentLaneBehaviour
@claude reviewreview Incremental. The lane's own mode detection decides: a verify round when unresolved claude[bot] threads exist, otherwise a normal review.
@claude review --model opusreview Incremental with model override. Runs an incremental review using claude-opus-5.
@claude review --model sonnetreview Incremental with model override. Runs an incremental review using claude-sonnet-5.
@claude full reviewreview From scratch, dedup disabled. Existing comments and threads are explicitly not dedup targets. Without that the plugin's dedup makes a re-review publish nothing (prismalens#410). Posts a ## Code review — full review summary.
@claude fixfixer Applies fixes on the PR branch (claude-fix.yml).
bare @claude …mention Anything not matching the verbs above.

Summons run on draft PRs (explicit intent overrides the draft skip), bypass skip_authors, and always run past the auto-pause counter. Fork-head PRs stay refused even when summoned (v1). Each summon is a full agent run, one per round, same economy as the fixer.

The mention stub must exclude all three verbs. The claude.yml caller stub carries a caller-level if: excluding comment bodies containing @claude fix, @claude review, or @claude full review. Those verbs belong to the fixer and review lanes; without the exclusion each such comment fires two lanes on the same PR, which is also what ends the fixer's existing double-fire. All three checks are needed: @claude full review does not contain @claude review as a substring.

Review lane inputs

InputDefaultMeaning
default_modelclaude-sonnet-5 Default Claude model for the review lane, passed through to anthropics/claude-code-action@v1 as --model inside claude_args (the action has no model input; CLI flag pass-through is the only available mechanism). Sonnet is the deliberate default: the review lane is the highest-volume Claude spend across the three consumer repos. Can be overridden per-run via summon comment (@claude review --model opus → claude-opus-5; @claude review --model sonnet → claude-sonnet-5; anything else, including automatic pull_request rounds, uses default_model). Allowlist, not extraction: the comment body is read strictly by workflow contains() expressions and never leaves them. It must never reach a prompt, a shell string, or claude_args. The override is implemented as fixed contains() checks mapping to pinned model-ID literals so no attacker-supplied text is ever interpolated into a command (the reason the syntax looks rigid). Known gap: @claude full review --model opus does not switch models. It falls through to default_model because the literal @claude review --model opus is not a substring of it. Runtime status: which model IDs actually work is set by the repo's CLAUDE_CODE_OAUTH_TOKEN subscription tier, not by this input. default_model pass-through is proven at runtime (2026-08-21, mage-memory#176). The per-run --model override is still unexercised. The callee repo gained CI on 2026-08-21 (tests.yml). Before that nothing verified it at all.
skip_authorsdependabot[bot] Comma-separated PR author logins whose automatic pull_request rounds are skipped entirely: no review, no verify, no liveness comment. Matching is exact-login (the list is delimiter-wrapped), so bot never collides with dependabot[bot]; use no spaces after the commas. A @claude review summon bypasses the list: manual intent wins.
auto_pause_rounds5 Automatic rounds allowed on one PR before the lane pauses itself. The count lives in the liveness marker and only automatic rounds that actually ran increment it. On pause the lane posts auto-paused after N automatic rounds instead of reviewing. Monotonic. v1 never resets it, so a summon resumes for exactly that one run. Raised 3 → 5 on 2026-08-21: three ran out on long-lived PRs, which then went silently unreviewed on every later push (mage-memory#176 landed two fix commits that way). A resettable counter is the real fix and is not built yet.

Reviewers left 3 comments. One @claude fix or three?

One. One summon comment per round. This is the @claude fix trigger, not a reply protocol; fix replies always go in-thread: @claude fix. The fixer's prompt tells it to read all unresolved review threads on the PR and address each, replying in every thread it touched with the fix commit SHA. Commenting per-thread would start one full agent run per comment (they serialize per-PR, but each spends subscription for nothing). Add scoping words only to exclude: e.g. @claude fix — only the two SCHEMA.md threads, leave the API design one for me.

Who resolves which thread?

Thread authorAfter a fix landsAfter a decline/defer
CodeRabbit CodeRabbit: batch ALL fixes, push, reply in each thread with the SHA (never the word "resolve" in a reply, since it parses as a command and no-ops), then spend one @coderabbitai review: it re-verifies and self-resolves what's genuinely addressed. Threads it leaves open get individually resolved with stated rationale (operator, or session under operator credential). Bare @coderabbitai resolve is discouraged, because it blanket-resolves with zero validation; reserve it for rounds that are entirely declines/deferrals with dispositions already stated. Operator resolves, after stating the disposition in-thread and waiting ~60s for its counter-reply. Point at a tracking issue by number.
claude[bot] (review lane) claude[bot] re-evaluates upon in-thread human reply and resolves verified fixed threads directly, citing the commit SHA and what it checked. Threads left open stay for human judgment. Operator resolves with reasoning in-thread.
HumanWhoever opened it resolves it.
Never let the fixer resolve anything. It is denied the tools, and the deny list is load-bearing: threads are the only thing standing between a pushed "fix" and a merge. The fixer fixes and replies; verification belongs to a different party. Disputes: operator tie-breaks.

Reading the liveness comment

Every PR gets one auto-updated comment from github-actions[bot], marked <!-- claude-review-liveness rounds=N sha=<head> -->. Match the marker prefix, never the whole string. The fields change, and since 2026-08-21 the set of fields does too, so an exact-string matcher silently stops seeing the comment. sha= names the head that last received a posted review; it is absent until one has. It advances only when the run actually published. A green run that posted nothing leaves it alone, so nothing later mistakes those commits for reviewed. Groundwork for incremental review; nothing reads it yet. Four verdicts:

  • "reviewed abc12345 and posted N inline / M summary comment(s)": the reviewer ran and published.
  • "posted nothing": this head has no machine review on record; silence is never approval. First-line re-request is @claude full review (dedup off), not another push.
  • "auto-paused after N automatic rounds at abc12345 — re-request with @claude review": the lane hit auto_pause_rounds and stopped reviewing this PR automatically. A paused PR is not reviewed on push; waiting for one waits forever. Summon, or report the pause. Not review evidence, so never enqueue on it.
  • "did not run … no CLAUDE_CODE_OAUTH_TOKEN reached this lane": the secret is not mapped in the caller stub (inherit does not cross owners). No review on record.

A PR that edits claude-code-review.yml itself is never reviewed by the lane (self-skip is a security control) and no summon fixes that one: label it coderabbit_review for a CodeRabbit read instead.

Fork PRs

Fork heads never reach the reviewer: GitHub withholds the repository's secrets from fork code, and the lane deliberately does not use pull_request_target. A summon does not override this (v1). Instead a fork-notice job upserts a comment marked <!-- claude-review-fork-notice --> saying so and pointing at the coderabbit_review label, so a fork PR is refused out loud rather than silently quiet. Fork pull_request runs also hold a read-only GITHUB_TOKEN unless the repo enables Send write tokens to workflows from fork pull requests (off by default); when the comment is denied the job falls back to a workflow warning annotation carrying the same text.

When to spend a CodeRabbit review

Apply the coderabbit_review label (or comment a bare @coderabbitai review). A PR without the label shows "Review skipped: excluded by label configuration", which is the valve working, not an error. It's an org-wide, ~40-min-cooldown counter. Spend it on security-sensitive paths, workflow changes, or a second opinion; never routinely. Batch your fixes before re-requesting.

Merging

  • prismalens, sreforge: gh pr merge N --squash enqueues; the queue tests a speculative merge onto main and lands it. No more update-branch / BEHIND cascades, no full-CI reruns per sibling merge.
  • mage-memory: classic squash (merge queue is org-only). Update-branch still applies there.
  • Bots never merge, anywhere. The fixer is tool-denied both gh pr merge and the REST merge endpoint.

4Standing doctrine

  • A green job is never evidence a review happened. The action exits success when the reviewer posts nothing. Only posted output counts: inline threads, a ## Code review summary, the liveness count.
  • Automatic review is finite; a summon is the only resume. Automatic rounds stop after auto_pause_rounds and the counter is monotonic in v1, so pushing more commits produces nothing. Anything that waits on a machine review must read the liveness verdict, not the absence of one.
  • Canary before trust. After any lane lands on a new repo or a workflow change merges: open a trivial docs PR, wait for the review run, read the liveness comment. Close the canary unmerged.
  • Consumers hold thin caller stubs; lane logic changes happen in prismalens/gh-workflows only. Reusable workflows live in canon (prismalens/gh-workflows); consumers hold thin caller stubs. Lane logic changes happen in prismalens/gh-workflows only.
  • CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1 stays on every lane until upstream print mode survives background-subagent gaps (async launches end one-shot sessions before results arrive, the bug that silenced reviews for two days). Unpin = remove the env var, then re-canary; a green run is not verification.
  • Reviewer lanes are read-only; the fixer holds the only model-adjacent write, fork-guarded (resolve-pr job) and tool-denied from reviewing/resolving/merging. Don't add writes to any other lane.
